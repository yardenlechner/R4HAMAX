# התקנה והרצה ב־Mainframe

## 1. דרישות

- z/OS עם TSO/E REXX ו־EXECIO התומך ב־VBS. IBM הוסיפה תמיכה ברשומות
  spanned ל־EXECIO ב־z/OS V2R1; ההרצה המיועדת היא ב־TSO/E תחת IKJEFT01.
- SMF 70-1 שנאסף על ידי RMF וקובץ dump תקין, או הרשאת קריאה ל־logstream.
- הרשאות הקצאה/קריאה/כתיבה המתאימות ל־DDs שב־JCL.
- התאמת JOB card, UNIT, SPACE, REGION ומחלקות spool לנהלי האתר.

אין צורך ב־Python, Regina, SAS או ספרייה חיצונית בזמן ההרצה ב־z/OS.

## 2. הכנת הספריות והעברה

אפשר להשתמש בספריות קיימות. אם נדרשות חדשות, הקצה דרך ISPF 3.2:

| ספרייה לדוגמה | סוג | פורמט |
|---|---|---|
| `YOURHLQ.REXX` | PDS/PDSE של טקסט | FB, LRECL 80 |
| `YOURHLQ.JCL` | PDS/PDSE של טקסט | FB, LRECL 80 |

העתק את תוכן `src/R4HAMAX.rexx` ל־`YOURHLQ.REXX(R4HAMAX)`.
העבר **כקובץ טקסט עם המרת ASCII ל־EBCDIC**, בלי BOM ובלי מספרי שורות.
בדוק ב־ISPF שהשורה הראשונה היא `/* REXX... */`, ושסימני `|`, `\`,
גרשיים ופסיקים נשמרו לפי code page של האתר. ההסברים בעברית נשארים
ב־GitHub; המקור וה־JCL משתמשים בתווי ASCII בלבד.

העבר את קובצי ה־JCL לממברים, למשל EXISTING, EXTRACT, LOGSTRM ו־SELFTEST.
שמות קובצי GitHub הארוכים אינם שמות ממבר חובה.

## 3. SELFTEST

התאם `jcl/SELFTEST.jcl`, הגש ובדוק SYSTSPRT. נדרש:

```text
SELFTEST PASS: parser, bounds, flags, dates, filters,
deduplication, Top-N, hourly mean and report.
```

בדיקה זו פועלת על רשומות סינתטיות בזיכרון. היא מאמתת גם שסימני המקור
הועברו נכון, אך אינה בודקת קריאה פיזית מ־VBS.

## 4. הרצה מול dump קיים

ב־`RUN_EXISTING.jcl` החלף:

| מקום | מה לשים |
|---|---|
| `SYSEXEC` | ספריית ה־REXX שבה נמצא R4HAMAX |
| `SMFIN` | פלט SMF dump בינארי תקין |
| `DATE=2026251` | היום המבוקש בפורמט YYYYDDD |
| `SID=*` | SID ידוע בהפעלה הראשונה, למשל SYSA |

התחל עם `DEBUG=Y`, והשווה אורך רשומה ו־triplets לתיעוד IBM ולרשומה
ידועה. אחרי אימות המיפוי עבור ל־`DEBUG=N`.

REPORT ו־CSVOUT בדוגמאות נכתבים ל־spool בפורמט VB באורך עד 256 תווי
תוכן, ועוד 4 בתים RDW. אל תגדיר REPORT כ־FB 80: שורת הדירוג ארוכה יותר.

אם רוצים לשמור CSV ב־dataset במקום spool, החלף את CSVOUT, למשל:

```jcl
//CSVOUT DD DSN=YOURHLQ.R4HA.CSV,
//          DISP=(NEW,CATLG,DELETE),UNIT=SYSDA,
//          SPACE=(TRK,(5,5),RLSE),
//          DCB=(RECFM=VB,LRECL=260,BLKSIZE=0)
```

בחר שם חדש או פעל לפי נוהל האתר לקובץ קיים. להורדת **פלט הטקסט**
למחשב, השתמש בהמרת EBCDIC לטקסט; אל תשנה את קובץ SMF המקורי.

## 5. חילוץ באמצעות IFASMFDP

`RUN_EXTRACT.jcl` קורא archive נתון, בוחר `TYPE(70(1))`, כותב dataset
זמני ומפעיל REXX רק כאשר EXTRACT מסתיים ב־RC=0. המצב הוא DUMP בלבד.
מוחקים בסוף רק את dataset העבודה הזמני, לא את מקור ה־SMF.

בדוגמה נבחרים שלושה תאריכים: היום הקודם, היום המבוקש והיום שאחריו.
זו רשת ביטחון לדוגמה עבור גבולות RMF מול זמן כתיבת SMF, ולא הבטחה
לטיפול בכל עיכוב כתיבה אפשרי. מקור הארכיון חייב להכיל בפועל את הרשומות.
התוכנית בוחרת לבסוף רק דגימות שהתאריך שלהן תואם ל־DATE ול־DAYMODE.

## 6. חילוץ מ־logstream

`RUN_LOGSTREAM.jcl` דומה, אך משתמש ב־IFASMFDL וב־LSNAME של האתר.
הדוגמה משתמשת במפורש ב־`OPTIONS(DUMP)`; אין לשנות ל־ARCHIVE/DELETE
לצורך דוח זה. אם כמה logstreams כוללים אותם records, יהיו כפילויות;
התוכנית מסירה כפילויות לפי מפתח המדידה המתועד.

## 7. טיפול בתוצאה

1. בדוק שהשלבים אכן רצו ושה־DDs הופקו.
2. בדוק RC והודעות SYSTSPRT/SYSPRINT.
3. בדוק VALID, מסננים ודחיות בדוח.
4. השווה מספר דגימות ללוח הזמנים הצפוי של RMF. לא תמיד יש 96 ביום:
   IPL, שינויי interval, חוסרים ושינויי שעון יכולים לשנות את הכמות.
5. אמת את הרשומה שבדירוג 1 מול מקור ידוע באותו SID ובאותו זמן.

אם יש RC=12, כל פלט שכבר נכתב עלול להיות חלקי ואינו תוצאה לשימוש.
