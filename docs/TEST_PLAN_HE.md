# בדיקות וקריטריוני קבלה

## בדיקות שבוצעו בפיתוח

הקוד הורץ על Windows עם Regina REXX 3.9.7. הבדיקות משתמשות
באותן פונקציות REXX של המימוש, לא ב־parser חלופי ב־Python.
`tests/run_checks.py` משווה גם חישובי תאריך ל־datetime של Python.

| בדיקה | תוצאה נדרשת |
|---|---|
| פיק ודירוג | 160 לפני 130 לפני 100 |
| ממוצע שעה | 100,160,130 נותנים 130 |
| סינון SID | דגימת SYSB אינה משפיעה על SYSA |
| כמה SIDs | דירוגים עצמאיים |
| ערכי קצה | 0 תקין; 4294967295 מפוענח כ־unsigned |
| תיקו | סדר הקלט נשמר |
| כפילות | אינה מגדילה N או CSV |
| כפילות סותרת | כשל עם הודעת RC=12 |
| packed שלילי / שעה לא תקינה / משך אפס | דחייה |
| גבול section / NUM שאינו 1 / רשומה קצרה | דחייה בטוחה |
| חצות | END ביום החדש; START ביום הקודם |
| לוח שנה | leap 2000/2400, non-leap 1900/2100 ועוד |
| STF bit 3 OFF | נשמר עם אזהרה |
| samples skipped | אזהרה, בלי פסילה אוטומטית של LAC |
| 258 records בשתי מנות | גם נתונים שמגיעים יחד עם EOF RC=2 מעובדים |
| I/O מדומה | ספירת כתיבות, סגירת DDs וכשל קריאה/כתיבה |
| קלט ריק | אין crash; אין דגימות |
| REPORT | מופק בפועל ב־REXX |
| קובצי מקור ו־JCL | ASCII, עד 72 תווים בשורה |

הרצה חוזרת:

```text
python tests/run_checks.py regina
```

בדיקות ה־I/O המקומיות מחליפות **רק** את פקודות ADDRESS TSO בסימולטור
EXECIO בתוך עותק זמני ב־`.work`. הן אינן בודקות QSAM או TSO אמיתי.
הן אינן מבטיחות תאימות מלאה בין Regina ל־TSO/E; לכן נדרש גם SELFTEST
ב־Mainframe ובדיקת dataset אמיתי.

## בדיקות קבלה ב־z/OS — עדיין לביצוע באתר

1. **העברת מקור:** הרץ SELFTEST.jcl. אם מתקבלת שגיאת תחביר, בדוק
   המרת code page, חיתוך שורות ותווי `|` ו־`\` לפני שינוי הלוגיקה.
2. **VBS אמיתי:** בחר dump מוכר של 70-1, הרץ DEBUG=Y, אמת את אורך
   הרשומה ו־Product/CPU triplets. בדוק גם רשומה ש־QSAM נדרש להרכיב
   ממקטעים. תמיכה ב־VBS של הספרייה אינה נבדקת בסימולציה המקומית.
3. **השוואת שדה:** עבור SID אחד, קח לפחות חמש רשומות ידועות. אמת
   LAC, start, end ו־duration מול formatter/RMF/כלי קיבולת אמין.
   בהשוואה ל־HEX, השתמש במיפוי של release האתר.
4. **פיק:** השווה את MAX לכל הרשומות של יום מוכר ואת חמש הגדולות.
   כלי שמשייך לפי START מחייב DAYMODE=START בעת ההשוואה.
5. **חצות:** בדוק interval שמתחיל ביום הקודם ומסתיים בדיוק בחצות.
   ב־END הוא צריך להיכלל ביום החדש ולהיכלל בשעה 00.
6. **ספירות וחוסרים:** בדוק כמות records מול dump utility ומול
   תדירות RMF הצפויה. מחק interval רק מעותק בדיקה; ודא שהמשתמש
   מזהה ירידה ב־N ואינו מפרש זאת כאישור לכיסוי שעה מלאה.
7. **משכים שונים:** השתמש בנתונים עם שינוי interval; בדוח השעתי
   MIN_MS/MAX_MS שונים. MEAN נשאר ממוצע דגימות לא משוקלל.
8. **כמה מערכות:** ערבב שני SIDs ייחודיים ודא שהפיקים נשארים נפרדים.
   אין להכניס לאותה ריצה שתי מערכות עם אותו SID.
9. **כפילות וסתירה:** שכפל רשומה בעותק בדיקה. היא תיספר ככפילות.
   אם משנים LAC באותו מפתח, הריצה חייבת להיכשל ופלט חלקי נפסל.
10. **DD/RC:** בדוק SMFIN חסר, REPORT לא ניתן לכתיבה, CSVOUT חסר
    כש־CSV=Y, ו־DATE ללא תוצאות. אמת גם את ה־RC שה־scheduler רואה.
11. **חילוץ:** הרץ כל JCL רלוונטי באתר, בדוק SYSPRINT, ודא RUN אינו
    רץ כש־EXTRACT נכשל. ודא שמקור SMF נשאר ללא שינוי.
12. **נפח:** מדוד CPU ו־storage ביום מייצג. הגדל REGION בהתאם
    לנהלי האתר או פצל לפי יום; היסטוריית כפילויות גדלה עם נפח הקלט.

יש לתעד גרסת z/OS/RMF, זמן הריצה, סוג הקלט, פרמטרים, ספירות,
תוצאת השוואה ו־RC. אפשר לתעד ללא העלאת SMF גולמי ל־GitHub.

## תנאי קבלה

SELFTEST עבר ב־TSO/E, JCL ו־VBS אומתו באתר, השדות והפיק זהים למקור
ההשוואה, וכל דחייה/אזהרה מוסברת. אי־התאמה ל־SCRT לבדה אינה הוכחה
לבאג, משום שהמדדים והגדרת השעה עשויים להיות שונים.
